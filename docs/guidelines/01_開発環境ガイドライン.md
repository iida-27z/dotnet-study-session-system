# 開発環境ガイドライン

## 1. 目的
- 本ガイドラインは、開発者全員が同一条件で開発・テスト・レビューを実施するための共通ルールを定義する。

## 2. 適用範囲
- 本リポジトリの全開発者。
- 対象は Web アプリ、DB 関連作業、ユーザー登録バッチ、およびテスト作業。

## 3. 標準開発環境
- 開発環境は `.devcontainer` の設定に従う。
- `.NET SDK` は `global.json` で固定されたバージョンを使用する。
- DB は `PostgreSQL` を使用する。
- 開発環境は`GitHub CodeSpaces` の利用を推奨とし、次点として`VS Code` と`DevContainer` の利用を推奨する。

## 4. 初期セットアップ手順

* **GitHub CodeSpacesの場合**
	1. GitHubのリポジトリページにアクセスし、CodeSpaces を起動する。
	2. フォルダを信頼するかの確認画面が表示されるので、信頼することを選択する。

* **VS Code + DevContainerの場合**
	1. リポジトリをクローンする。
	2. VS Code でフォルダを開き、Dev Container で再度開く。
	3. 初回起動時に `.devcontainer/.env` が存在しない場合、`.env.example` から自動生成されることを確認する。

## 5. 日常開発で使用する基本コマンド

### 5.1 依存関係の復元
```bash
dotnet restore
```

### 5.2 フォーマット
```bash
dotnet format
dotnet format --verify-no-changes
```

### 5.3 ビルド
```bash
dotnet build
```

### 5.4 テスト
```bash
dotnet test
```

### 5.5 Web アプリ起動
```bash
dotnet run --project src/StudySession.Web/StudySession.Web.csproj
```

### 5.6 バッチ起動
```bash
dotnet run --project src/StudySession.Batch/StudySession.Batch.csproj
```

## 6. Git hooks と機密情報対策
- pre-commit で `gitleaks protect --staged` を実行する。
- コミット時に機密情報が検知された場合、検知内容を修正してから再コミットする。
- 例外的にフックを無効化してコミットしてはならない。

## 7. 推奨 VS Code 設定
- C# の既定フォーマッターは `ms-dotnettools.csharp` を使用する。
- `editor.formatOnSave` を有効とする。

## 8. トラブルシューティング
- DB 接続に失敗する場合:
	- `.devcontainer/.env` の DB 接続情報を確認する。
	- コンテナ起動順と PostgreSQL 側の正常起動を確認する。
- pre-commit で失敗する場合:
	- gitleaks の検知結果を確認し、機密情報を除去して再実行する。

## 9. 更新ルール
- 開発環境を変更する PR では、本ドキュメントの更新を必須とする。
- 変更時は `docs/specs` と矛盾しないことを確認する。
