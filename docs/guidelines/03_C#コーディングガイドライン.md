# C#コーディングガイドライン

## 1. 目的
- 本ガイドラインは、保守性・可読性・安全性を担保するための最小限かつモダンな C# 規約を定義する。

## 2. 適用範囲
- `src` 配下の全 C# プロジェクト。
- `tests` 配下の全テストプロジェクト。

## 3. 基本方針
- 「自明で読みやすいコード」を優先する。
- ルールは最小限に絞り、フォーマッターによる自動整形を前提とする。
- 仕様と実装が乖離しないよう、必要に応じて `docs/specs` を更新する。

## 4. 必須規約

### 4.1 Null 安全
- Nullable Reference Types（NRT）を有効として実装する。
- null 許容型が必要な理由を明確にする。

### 4.2 名前空間
- file-scoped namespace を使用する。

### 4.3 非同期メソッド
- `async` メソッド名には `Async` サフィックスを付与する。

### 4.4 var 利用
- 右辺から型が明確に読み取れる場合のみ `var` を使用する。
- 型が読み取りづらい場合は明示型を使用する。

### 4.5 モダン構文
- 必要に応じて `record`、`required`、`init` を活用する。

### 4.6 XML コメント
- `public` メンバーには XML ドキュメントコメントを必須とする。

## 5. 命名規約
- クラス・メソッド・プロパティ: PascalCase
- インターフェース: `I` + PascalCase
- ローカル変数・引数: camelCase
- 非公開フィールド: `_camelCase`
- 定数: PascalCase（業務上特別な理由がある場合のみ UPPER_SNAKE_CASE を許可）

## 6. レイヤリング原則
- Domain 層は他層へ依存しない。
- Application 層は Domain 層のみに依存する。
- Infrastructure 層は Domain/Application の実装詳細を提供する。
- Web/Batch 層は Application 経由でユースケースを呼び出す。

## 7. 例外処理とログ
- 例外は握りつぶさず、意味のある粒度でハンドリングする。
- 機密情報をログに出力しない。
- 例外ログには原因追跡に必要な文脈情報を含める。

## 8. フォーマットと品質チェック
- 保存時フォーマットを前提とする。
- PR 前に次を実行する。

```bash
dotnet format --verify-no-changes
dotnet test
```

## 9. テスト実装ルール
- テストは Arrange-Act-Assert を基本構造として、コメントで各ブロックを明示する。
- テスト名は「対象_条件_期待結果」が読み取れる形式にする。
- テスト内容が読み取れる日本語のDisplayName を付与する。
- 不具合修正時は再発防止テストを追加する。

## 10. 禁止事項
- `#nullable disable` の常用。
- 意図のない `!`（null 許容抑制）多用。
- 巨大メソッド（単一責務から逸脱した処理の混在）。
- 例外を握りつぶして正常系として継続する実装。

## 11. 更新ルール
- 本規約を変更する場合、理由と影響範囲を PR に明記する。
