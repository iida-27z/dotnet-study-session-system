# 03_データモデル・DB要件

## 1. 文書の目的
本書は、PostgreSQL 上のデータモデル、主要テーブル、整合性制約、運用上の要件を定義する。
用語は 99_用語集 に従う。

## 2. DB 方針
1. DB エンジンは PostgreSQL を採用する。
2. 接続情報は環境変数から取得する。
3. アプリケーションからのアクセスは Dapper と生 SQL を使用する。
4. 文字コードは UTF-8 とする。
5. 日時は timestamptz を採用し、保存は UTC を基本とする。

## 3. 論理エンティティ
| エンティティ | 説明 |
|---|---|
| users | 認証・利用者情報 |
| study_sessions | 勉強会セッション情報 |
| session_participations | ユーザーごとの出欠情報 |

## 4. テーブル定義

### 4.1 users
| カラム | 型 | 必須 | 制約 | 説明 |
|---|---|---|---|---|
| user_id | uuid | Yes | PK | ユーザーID |
| login_id | varchar(64) | Yes | UNIQUE | ログインID |
| display_name | varchar(100) | Yes |  | 氏名 |
| email | varchar(254) | Yes | UNIQUE | メールアドレス |
| password_hash | varchar(255) | Yes |  | bcrypt ハッシュ |
| role | varchar(16) | Yes | CHECK role in ('User','Admin') | ロール |
| is_active | boolean | Yes | default true | 有効フラグ |
| created_at | timestamptz | Yes |  | 作成日時 |
| updated_at | timestamptz | Yes |  | 更新日時 |

備考:
1. password_hash には平文を保存しない。
2. login_id は英数字と記号の一部を許可し、空白を禁止する。

### 4.2 study_sessions
| カラム | 型 | 必須 | 制約 | 説明 |
|---|---|---|---|---|
| session_id | uuid | Yes | PK | 勉強会ID |
| title | varchar(200) | Yes |  | タイトル |
| description | text | No |  | 概要 |
| starts_at | timestamptz | Yes |  | 開始日時 |
| ends_at | timestamptz | Yes | CHECK ends_at > starts_at | 終了日時 |
| format | varchar(16) | Yes | CHECK format in ('Hybrid','OnsiteOnly','RemoteOnly') | 開催形式 |
| capacity_onsite | integer | Yes | CHECK capacity_onsite >= 0 | 対面枠 |
| capacity_remote | integer | Yes | CHECK capacity_remote >= 0 | リモート枠 |
| created_by_user_id | uuid | Yes | FK users.user_id | 主催者ユーザーID |
| created_at | timestamptz | Yes |  | 作成日時 |
| updated_at | timestamptz | Yes |  | 更新日時 |

備考:
1. format が OnsiteOnly の場合、capacity_remote は 0 とする。
2. format が RemoteOnly の場合、capacity_onsite は 0 とする。
3. format が Hybrid の場合、capacity_onsite と capacity_remote はいずれも 1 以上を推奨する。

### 4.3 session_participations
| カラム | 型 | 必須 | 制約 | 説明 |
|---|---|---|---|---|
| session_id | uuid | Yes | PK/FK study_sessions.session_id | 勉強会ID |
| user_id | uuid | Yes | PK/FK users.user_id | ユーザーID |
| attendance_status | varchar(16) | Yes | CHECK attendance_status in ('Unanswered','Onsite','Remote','Absent') | 参加ステータス |
| comment | varchar(500) | No |  | コメント |
| responded_at | timestamptz | No |  | 回答日時 |
| updated_at | timestamptz | Yes |  | 更新日時 |

備考:
1. 主キーは session_id と user_id の複合キーとする。
2. format が OnsiteOnly の場合、attendance_status=Remote は登録不可とする。
3. format が RemoteOnly の場合、attendance_status=Onsite は登録不可とする。

## 5. インデックス要件
| 対象 | インデックス | 目的 |
|---|---|---|
| users.login_id | UNIQUE INDEX | 認証検索の高速化 |
| users.email | UNIQUE INDEX | 重複登録防止 |
| study_sessions.starts_at | INDEX | 一覧表示の日時ソート高速化 |
| study_sessions.title | INDEX | キーワード検索補助 |
| session_participations.user_id | INDEX | ユーザー別参照の高速化 |
| session_participations.session_id + attendance_status | INDEX | 参加者名簿集計の高速化 |

## 6. データ整合性ルール
1. 定員超過登録はアプリケーション層で拒否する。
2. 出欠更新締切は開催前日 18:00 とし、締切超過時の更新を拒否する。
3. users.is_active=false のユーザーは新規ログイン不可とする。
4. FK 制約違反となる削除は許可しない。

## 7. セキュリティ要件
1. パスワードハッシュは bcrypt を利用する。
2. SQL は必ずパラメータ化する。
3. 接続文字列は環境変数で注入し、ソース管理へ平文保存しない。

## 8. 監査・運用要件
1. created_at と updated_at は全主要テーブルで必須とする。
2. 出欠更新時は updated_at を更新する。
3. バッチ登録時は成功/失敗の監査ログを残す。
