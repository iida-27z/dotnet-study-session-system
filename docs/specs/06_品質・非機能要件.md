# 06_品質・非機能要件

## 1. 文書の目的
本書は、本システムに求める品質特性と非機能要件を定量的に定義する。
用語は 99_用語集 に従う。

## 2. 適用範囲
1. Web アプリ
2. ユーザー登録バッチ
3. PostgreSQL
4. テスト基盤と CI 実行

## 3. 性能要件
### 3.1 Web 応答性能
| 対象 | 指標 | 目標値 |
|---|---|---|
| ログイン | 応答時間 p95 | 1.0秒以内 |
| 勉強会一覧 | 応答時間 p95 | 2.0秒以内 |
| 勉強会詳細 | 応答時間 p95 | 2.0秒以内 |
| 出欠更新 | 応答時間 p95 | 1.5秒以内 |

条件:
1. 同時利用者 100 ユーザー相当を想定する。
2. テストデータは勉強会 1,000 件、参加情報 50,000 件を目安とする。

### 3.2 バッチ性能
| 対象 | 指標 | 目標値 |
|---|---|---|
| 単件モード | 1件登録処理時間 | 2秒以内 |
| CSV モード | 1,000件登録処理時間 | 5分以内 |

## 4. 可用性要件
1. 月間稼働率目標は 99.5% 以上とする。
2. 計画停止は事前通知し、稼働率計算から除外する。
3. RTO は 4 時間以内、RPO は 24 時間以内を目標とする。

## 5. セキュリティ要件
### 5.1 認証・認可
1. 認証方式は Cookie 認証を利用する。
2. パスワードは bcrypt ハッシュを使用する。
3. ロールは User/Admin の2種とする。

### 5.2 セッション管理
1. 認証 Cookie は HttpOnly、Secure、SameSite=Lax を有効化する。
2. 無操作タイムアウトは 30 分とする。

### 5.3 入力・出力保護
1. 入力値はサーバー側で必ず検証する。
2. SQL は全件パラメータ化し SQL インジェクションを防止する。
3. 出力エスケープで XSS を防止する。
4. CSRF 対策を有効化する。

### 5.4 機密情報保護
1. DB 接続情報は環境変数で管理する。
2. 秘密情報はリポジトリへコミットしない。
3. ログにパスワード平文を出力しない。

## 6. 信頼性要件
1. 例外はアプリケーションでハンドリングし、利用者向けに 500 ページを表示する。
2. 重要処理は失敗時にリトライ戦略を設ける。
3. データ更新処理は整合性制約を満たすこと。

## 7. 運用・監視要件
1. Web はアクセスログ、認証ログ、例外ログを記録する。
2. Batch は実行履歴、成功件数、失敗件数、失敗理由を記録する。
3. ログには時刻、レベル、機能、相関IDを含める。
4. アラート対象は認証異常増加、500エラー増加、バッチ失敗とする。

## 8. 保守性要件
1. アーキテクチャはレイヤ分離を維持する。
2. Domain/Application/Infrastructure の責務混在を禁止する。
3. 設計変更時は specs を同時更新する。

## 9. テスト要件
### 9.1 単体テスト
1. Domain/Application を中心に実装する。
2. 主要ビジネスルールの正常系/異常系を網羅する。

### 9.2 結合テスト
1. TestContainers を使用し PostgreSQL と接続した試験を実施する。
2. users、study_sessions、session_participations の主要 CRUD を検証する。

### 9.3 受入基準
1. 主要ユースケースの自動テストを必須とする。
2. 行カバレッジ目標は 80% 以上とする。
3. CI でテスト失敗時はマージ不可とする。

## 10. 互換性・対応環境
1. 対応ブラウザは最新の主要モダンブラウザを対象とする。
2. サーバー実行環境は .NET と PostgreSQL の組み合わせを前提とする。

## 11. 監査要件
1. ログイン成功/失敗を記録する。
2. 勉強会作成と出欠更新を記録する。
3. バッチ実行と登録結果を記録する。

## 12. 例外画面品質
1. 403/404/500 画面はユーザーの次操作導線を提供する。
2. 内部エラー詳細を画面表示しない。
