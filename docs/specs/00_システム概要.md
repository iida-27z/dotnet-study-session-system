# 00_システム概要

## 1. 文書の目的
本書は、社内勉強会管理システムの全体像、対象範囲、構成要素を定義する。
詳細仕様は docs/specs 配下の個別文書を参照する。
ドメイン用語は 99_用語集 に従う。

## 2. 背景
社内勉強会を継続的に運営するうえで、テーマ企画、参加表明、出欠管理、ユーザー登録を統一的に扱う仕組みが必要である。
本システムは Web アプリ、DB、ユーザー登録バッチで構成される。

## 3. システムの目的
1. 勉強会の企画と公開を標準化する。
2. 参加者が対面/リモートの空き状況を確認し、出欠を更新できるようにする。
3. ユーザー登録を手動バッチで安全に運用できるようにする。

## 4. 対象ユーザー
| 区分 | 説明 |
|---|---|
| User | 一般利用者。ログイン、一覧参照、勉強会作成、出欠更新を行う。 |
| Admin | 管理運用者。User の権限に加え、運用監視やバッチ実行を担う。 |

## 5. システム構成
1. Web アプリ
    * 勉強会一覧、勉強会作成、勉強会詳細、出欠更新、ログイン機能を提供する。
2. PostgreSQL
    * ユーザー、勉強会、出欠情報を保持する。
3. ユーザー登録バッチ
    * 手動実行コンソールでユーザー登録を行う。単件入力と CSV 一括取込に対応する。

## 6. スコープ
1. ログイン認証（Cookie 認証）
2. 勉強会の作成、一覧表示、詳細表示
3. 出欠ステータス更新（未回答、対面出席、リモート出席、欠席）
4. 参加者名簿表示
5. ユーザー登録バッチ（手動）
6. 403/404/500 エラーページ
7. 単体テストおよび TestContainers 結合テスト

## 7. 非スコープ
1. 外部認証基盤との連携（SSO、OAuth、SAML）
2. メール通知、チャット通知
3. 勉強会アーカイブ公開サイト
4. キャンセル待ち管理
5. モバイルネイティブアプリ

## 8. 決定事項
1. DB エンジンは PostgreSQL とする。
2. 認証は Cookie 認証を採用する。
3. パスワードは bcrypt ハッシュで保存し、平文保存しない。
4. ORM は利用せず、Dapper と生 SQL で実装する。
5. DB 接続情報は環境変数から取得する。
6. 勉強会作成は全ユーザーに許可する。
7. 定員超過時は先着で受付終了とする。
