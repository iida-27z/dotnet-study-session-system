# 05_ユーザー登録バッチ要件

## 1. 文書の目的
本書は、ユーザー登録バッチの機能要件、入力要件、実行手順、エラー処理を定義する。
用語は 99_用語集 に従う。

## 2. 概要
1. 本バッチは手動実行のコンソールアプリとして運用する。
2. 実行主体は Admin とする。
3. 登録対象は users テーブルとする。
4. パスワードは登録時に bcrypt ハッシュ化する。

## 3. 実行モード
| モード | 説明 |
|---|---|
| 単件入力モード | コンソールで1件ずつ入力し登録する。 |
| CSV 一括取込モード | CSV ファイルパスを入力し、複数件を登録する。 |

## 4. 必須入力項目
| 項目 | 必須 | 制約 |
|---|---|---|
| ログインID | Yes | 1〜64文字、一意 |
| 氏名 | Yes | 1〜100文字 |
| メールアドレス | Yes | RFC準拠形式、一意 |
| 初期パスワード | Yes | 12文字以上、英字大小/数字/記号を含む |
| ロール | Yes | User または Admin |

## 5. 単件入力モード要件
1. 実行時にモード選択メニューを表示する。
2. 各項目を順に入力させる。
3. 入力値検証に失敗した場合は理由を表示し再入力を要求する。
4. 最終確認後に登録し、結果を表示する。

## 6. CSV 一括取込モード要件
1. CSV ファイルパスを受け取り、存在確認を行う。
2. CSV ヘッダは次を必須とする。
    * login_id
    * display_name
    * email
    * initial_password
    * role
3. 各行を独立して検証・登録する。
4. 不正行はスキップし、理由を記録する。
5. 実行結果として総件数、成功件数、失敗件数を表示する。
```csv
login_id,display_name,email,initial_password,role
csv_001,山田太郎,yamada@example.com,Password123!,User
csv_002,鈴木花子,suzuki@example.com,Password123!,Admin
csv_003,田中一郎,tanaka@example.com,Password123!,User
```

## 7. 重複と更新方針
1. login_id または email が既存と重複する場合は登録失敗とする。
2. 初版では既存ユーザー更新を行わない。
3. 既存ユーザーの属性変更は別機能とする。

## 8. バリデーション要件
1. ログインIDは前後空白をトリムし、空文字を禁止する。
2. メールアドレスは形式検証を行う。
3. ロール値は User/Admin 以外を拒否する。
4. 初期パスワードはポリシー違反時に拒否する。

## 9. セキュリティ要件
1. 初期パスワードは受領後すぐに bcrypt でハッシュ化する。
2. 初期パスワード平文をログに出力しない。
3. SQL はパラメータ化する。
4. 接続情報は環境変数から取得する。

## 10. エラー処理要件
1. DB 接続失敗時はエラーコードと概要を表示して異常終了する。
2. CSV 解析失敗時は行番号と原因を表示する。
3. 予期しない例外は実行IDとともに記録する。

```
>
```


## 12. ログ要件
1. 実行開始時刻、実行者、モードを記録する。
2. 各行の成功/失敗と失敗理由を記録する。
3. 実行終了時に件数サマリーを記録する。
4. 監査目的で最低 1 年保存する。

## 13. トランザクション要件
1. 単件モードは1件単位でコミットする。
2. CSV モードも1件単位でコミットし、失敗行があっても継続する。
3. 全件ロールバックは行わない。

## 14. 運用要件
1. 手動実行手順書を整備する。
2. 実行結果ログは運用担当が確認する。
3. 異常終了時は再実行手順に従って復旧する。

## 15. テスト要件
1. 入力検証ロジックの単体テストを実装する。
2. ハッシュ化ロジックの単体テストを実装する。
3. PostgreSQL TestContainers を利用した登録処理の結合テストを実装する。
4. 正常系と異常系で CSV モード試験を実施する。
