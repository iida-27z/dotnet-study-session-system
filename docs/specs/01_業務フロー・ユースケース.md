# 01_業務フロー・ユースケース

## 1. 文書の目的
本書は、業務フローおよびユースケースを定義し、機能要件と実装責務の境界を明確化する。
用語は 99_用語集 に従う。

## 2. アクター
| アクター | 説明 |
|---|---|
| User | 社内ユーザー。ログイン、勉強会参照、作成、出欠更新を行う。 |
| Admin | 運用管理ユーザー。User の操作に加え、バッチ運用を担う。 |
| システム | Web アプリ、認証処理、DB、バッチ処理実行基盤。 |

## 3. 業務フロー一覧
| フローID | 名称 | 主アクター | 概要 |
|---|---|---|---|
| BF-01 | ログイン | User/Admin | 認証情報を検証し、一覧画面へ遷移する。 |
| BF-02 | 勉強会の参照と検索 | User/Admin | 一覧の確認、キーワード検索、詳細表示を行う。 |
| BF-03 | 勉強会の作成 | User/Admin | 勉強会情報を入力し、公開する。 |
| BF-04 | 出欠の更新 | User/Admin | 参加ステータスとコメントを更新する。 |
| BF-05 | ユーザー登録バッチ実行 | Admin | 手動コンソールでユーザー登録を実行する。 |

## 4. ユースケース定義

### UC-01 ログイン
| 項目 | 内容 |
|---|---|
| 目的 | 認証済みセッションを開始し、システム利用を可能にする。 |
| 主アクター | User/Admin |
| 事前条件 | ユーザーが users テーブルに登録済みで有効状態である。 |
| トリガー | ログイン画面でログイン操作を実行する。 |
| 基本フロー | 1) ログインIDとパスワードを入力する。2) システムが users のハッシュと照合する。3) 成功時に認証 Cookie を発行する。4) 勉強会一覧画面を表示する。 |
| 代替フロー | 認証失敗時は同画面にエラーメッセージを表示し再入力を促す。 |
| 事後条件 | 認証成功時はログイン状態となる。 |

### UC-02 勉強会の参照と検索
| 項目 | 内容 |
|---|---|
| 目的 | ユーザーが参加候補の勉強会を探し、詳細を確認できる状態にする。 |
| 主アクター | User/Admin |
| 事前条件 | ログイン済みである。 |
| トリガー | 勉強会一覧画面を開く。 |
| 基本フロー | 1) 一覧を表示する。2) キーワード/技術タグで検索する。3) 対面枠/リモート枠の空き状況を確認する。4) テーマ選択で詳細画面へ遷移する。 |
| 代替フロー | 一致データがない場合は「該当なし」を表示する。 |
| 事後条件 | ユーザーは対象勉強会の詳細を閲覧可能となる。 |

### UC-03 勉強会の作成
| 項目 | 内容 |
|---|---|
| 目的 | 新規勉強会を登録し、一覧で公開する。 |
| 主アクター | User/Admin |
| 事前条件 | ログイン済みである。 |
| トリガー | 勉強会作成画面で登録操作を実行する。 |
| 基本フロー | 1) テーマ、開始日時、終了日時、開催形式、定員、概要を入力する。2) システムが入力値を検証する。3) 勉強会を保存する。4) 一覧画面に遷移し登録結果を表示する。 |
| 代替フロー | 入力不備時は該当項目にエラーを表示し保存しない。 |
| 事後条件 | 主催者付きの勉強会セッションが登録される。 |

### UC-04 出欠の更新
| 項目 | 内容 |
|---|---|
| 目的 | 勉強会ごとの参加ステータスを更新する。 |
| 主アクター | User/Admin |
| 事前条件 | ログイン済みかつ対象勉強会が存在する。 |
| トリガー | 勉強会詳細画面で更新操作を実行する。 |
| 基本フロー | 1) 現在の開催形式とステータスを表示する。2) ユーザーが参加ステータスとコメントを入力する。3) システムが締切時刻と定員を確認する。4) 更新を保存し参加者名簿へ反映する。 |
| 代替フロー | 締切超過や満席時は更新を拒否し理由を表示する。 |
| 事後条件 | 参加ステータスが最新化される。 |

### UC-05 ユーザー登録バッチ実行
| 項目 | 内容 |
|---|---|
| 目的 | 新規ユーザーを安全に登録し、ログイン可能状態にする。 |
| 主アクター | Admin |
| 事前条件 | 実行者がバッチ実行環境へアクセス可能である。 |
| トリガー | 手動でバッチコマンドを実行する。 |
| 基本フロー | 1) 実行モードを選択する（単件入力/CSV一括取込）。2) 必須項目を受け取る。3) 検証後、パスワードをハッシュ化して users に登録する。4) 実行結果を出力する。 |
| 代替フロー | 不正データはスキップしエラーログへ記録する。 |
| 事後条件 | 成功件数と失敗件数が確定し、監査ログが残る。 |

## 5. 主要業務ルール
1. ロールは User/Admin の2種とする。
2. 勉強会作成は全ユーザーが可能とする。
3. 定員超過時は先着締切とし、キャンセル待ちは初版対象外とする。
4. 出欠変更は開催前日 18:00 を締切とする。
5. 認証失敗時はログイン画面内で再入力を要求する。

## 6. 例外シナリオ
1. 権限不足: 403 ページへ遷移する。
2. 非存在ページ: 404 ページへ遷移する。
3. サーバーエラー: 500 ページへ遷移する。
